Table Components: CSS Table vs CSS Grid

The Problem with colspan/rowspan

CSS Table Layout: Cannot implement colspan/rowspan with pure CSS - requires actual <td>/<th> elements.

CSS Grid Layout: Native spanning support with grid-column-end: span N and grid-row-end: span N.

Framework Integration Examples

CSS Table Components (t-*)

<t-table>
    <t-body if=${showData}>
        <t-row each:item=${items}>
            <t-cell>${() => item.name}</t-cell>
            <t-cell align="right">${() => item.value}</t-cell>
        </t-row>
    </t-body>
</t-table>

CSS Grid Components (g-*) - With Real Spanning

<g-table>
    <g-caption>Sales Summary Report</g-caption>
    <g-head>
        <g-row>
            <g-header colspan="2">Total Summary</g-header>
        </g-row>
    </g-head>
    <g-body if=${showData}>
        <g-row>
            <g-cell>${() => data.name}</g-cell>
            <g-cell rowspan="2">${() => data.value}</g-cell>
        </g-row>
    </g-body>
</g-table>

Recommendation

Use CSS Grid components (g-table, g-cell, g-header) when you need:

  • ✅ colspan or rowspan functionality
  • ✅ Complex table layouts with spanning
  • ✅ Modern, flexible grid-based design
  • ✅ Framework directives (if, await, each:)

Use CSS Table components (t-table, t-cell, t-header) when you:

  • ✅ Don't need colspan/rowspan
  • ✅ Want traditional table behavior
  • ✅ Need semantic table roles for accessibility
  • ✅ Framework directives (if, await, each:)
  • ❌ No spanning support
